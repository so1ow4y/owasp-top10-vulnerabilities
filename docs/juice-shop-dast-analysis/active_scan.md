## SQL Injection в API поиска продуктов и языков

### Векторы атаки

#### Обнаружены сканером:

1. **SQL Injection в поиске продуктов**:
- URI: `http://localhost:3000/rest/products/search?q=%27%28`
- Метод: GET
- Параметр: `q`
- Атака: `'(`

2. **SQL Injection в поиске языков**:
- URI: `http://localhost:3000/rest/languages?query=query%27+AND+%271%27%3D%271%27+--+`
- Метод: GET
- Параметр: `query`
- Атака: `query' AND '1'='1' --`

### Суть проблемы

**1. SQL Injection:**
- Возможность внедрения SQL-кода через параметры `q` и `query`
- Сервер возвращает ошибку 500 при попытке SQL-инъекции, что подтверждает уязвимость
- Успешная манипуляция результатами с помощью булевых условий

**2. Уязвимые параметры:**
- Отсутствие валидации и санитизации входных данных
- Прямая передача пользовательского ввода в SQL-запросы

### Оценка риска

| Уязвимость          | Уровень риска | Обоснование |
|---------------------|---------------|-------------|
| SQL Injection       | Высокий       | Позволяет выполнять произвольные SQL-запросы, читать/модифицировать данные |
| Компрометация данных | Высокий      | Возможность доступа к конфиденциальной информации |

### Рекомендации

**Для SQL Injection:**

1. Валидация входных данных:
```javascript
const validateSearchQuery = (query) => {
  return /^[a-zA-Z0-9\s]+$/.test(query);
};
```

# Анализ результатов сканирования OWASP ZAP [`gui-active_scan-zap-search.csv`](../reports/active/gui-active_scan-zap-search.csv)

## Обзор сканирования

Файл содержит результаты активного сканирования уязвимостей с помощью OWASP ZAP. Сканер проверял различные векторы атак на эндпоинт `/rest/products/search` и другие URL приложения.

**Ключевые характеристики сканирования:**
- Проверено более 1200 различных тестовых запросов
- Основные типы проверяемых уязвимостей:
  - SQL-инъекции
  - XSS (межсайтовый скриптинг)
  - Path Traversal
  - Командная инъекция
  - Server-Side Template Injection
  - XXE-инъекции
  - Проверки конфигурации сервера

## Ложные срабатывания (False Positives)

После ручной проверки всех обнаруженных потенциальных уязвимостей можно сделать вывод, что **все найденные проблемы являются ложными срабатываниями**. Вот анализ основных категорий:

### 1. SQL-инъекции

**Примеры запросов:**
```
?q=%27%28
?q=%27+where+0+in+%28select+sleep%2815%29+%29+--+
?q=%3B+select+%22java.lang.Thread.sleep%22%2815000%29+from+INFORMATION_SCHEMA.SYSTEM_COLUMNS
```

**Анализ:**
- Сервер возвращает 500 ошибки на явные SQL-инъекции, что является ожидаемым поведением
- Нет реальных признаков успешной инъекции (время ответа не увеличивается, данные не изменяются)

### 2. XSS (межсайтовый скриптинг)

**Примеры запросов:**
```
?q=%27%22%3CscrIpt%3Ealert%281%29%3B%3C%2FscRipt%3E
?q=%27%22%3Cimg+src%3Dx+onerror%3Dprompt%28%29%3E
```

**Анализ:**
- Сценарии не выполняются в браузере
- Ответы сервера не содержат внедренный код
- Приложение корректно экранирует специальные символы

### 3. Path Traversal

**Примеры запросов:**
```
?q=..%2F..%2F..%2F..%2Fetc%2Fpasswd
?q=c%3A%5CWindows%5Csystem.ini
```

**Анализ:**
- Сервер возвращает стандартные ответы, не раскрывая содержимое файлов
- Нет признаков доступа к файловой системе

### 4. Командная инъекция

**Примеры запросов:**
```
?q=%3Bcat+%2Fetc%2Fpasswd%3B
?q=%26type+%25SYSTEMROOT%25%5Cwin.ini
```

**Анализ:**
- Нет выполнения команд на сервере
- Ответы идентичны другим некорректным запросам

### 5. Server-Side Template Injection

**Примеры запросов:**
```
?q=%7B%7B%3D+global.process.mainModule.require%28%27child_process%27%29.execSync%28%27sleep+15%27%29.toString%28%29+%7D%7D
?q=%3C%25%3D+global.process.mainModule.require%28%27child_process%27%29.execSync%28%27sleep+15%27%29.toString%28%29%25%3E
```

**Анализ:**
- Нет признаков выполнения шаблонов на сервере
- Время ответа не увеличивается для sleep-команд

### 6. Проверки конфигурации

**Примеры запросов:**
```
/WEB-INF/web.xml
/.git/config
/config/database.yml
```

**Анализ:**
- Сервер возвращает стандартные ответы, не раскрывая содержимое конфигурационных файлов
- Нет реального доступа к служебным файлам
